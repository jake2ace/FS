# FreightSentinel 确认版流程

更新：2026-09-20。AI 作业务判断；首轮 high 思考 → max 思考复核 → 人工最终处理。OpenAI 充值暂不可用，用户选择先测试已有 DeepSeek 思考模式。

1. DeepSeek 首轮根据当前邮件正文和主题判断五种类别，并引用原文。非 BL_COMPARISON 记录类别后结束；此时 OK 只表示无需比较。
2. BL_COMPARISON 读取实际 SI / draft BL；可尝试本地重新解析和 OCR。AI 判断文件类型、提取七字段、统一写法和单位、逐项比较。
3. 七项可靠一致 → OK；可靠存在差异 → MISMATCH，列出字段、双方值和证据。
4. 无法分类、读不了、字段缺失、比较不确定、调用失败、JSON 无法解析或证据校验不通过 → 调用配置好的复核 AI 一轮。
5. 复核仍不确定、失败或未配置 → NEEDS_REVIEW + 原因，进入人工队列。缺失信息不能凭空补成确定值；不强求 AI 解决每封邮件。
6. 人工独立确认类别、原始邮件的检测结果、差异字段并记录处理说明。可以保存进度，或确认完成 → RESOLVED_BY_HUMAN。完成后结束，重新打开也只继续人工处理，不回 AI。

复核模式：同一个 deepseek-flash，两层 thinking=enabled；首轮 reasoning_effort=high（官方 low/high/max 的中间档）；复核 reasoning_effort=max。不是另一个更强模型，其实际改善必须通过测试确认。付费仍走现有 DeepSeek 余额。

七字段：shipper、consignee、notify_party、port_of_loading、port_of_discharge、container_count、gross_weight_kg。

## 副本

确定 MISMATCH 后，可按 AI 的 SI 读数生成原格式 BL 工作副本；先对实际生成文件进行 AI 核对。无法安全定位或核对失败则交人工。采纳时仅检查已审文件的哈希未变，不再调用 AI。采纳保留副本，不采纳删除服务器副本。原始附件和历史判断保留。

## 程序和 AI 的边界

程序只处理文件、校验结构/证据来源/AI 输出的一致性、路由和保存。生产流程不调用 classify_rules、extract_fields、compare_fields。未分类案件保留 category=null，显示在人工队列；人工确认类别前禁止导出完整提交。人工修改判断时，原 AI 结果留在历史里；修订副本不覆盖原件的检测结果。

当前附件输入仍以解析/OCR 文本为主；未新增原始图片多模态判断。高级 AI 不能恢复本来就不存在的附件或事实。

## 验证边界

离线测试验证路由、人工终止、密钥隔离、副本保留/删除，不能当成 AI 准确率。真实思考测试仅覆盖报告中列出的邮件，不代表 520 封全量通过。本次不开发公司提示词管理页面。
